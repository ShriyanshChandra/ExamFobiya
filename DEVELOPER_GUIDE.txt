1. EXECUTIVE SUMMARY & CORE MISSION
================================================================================
ExamFobiya is a comprehensive, production-grade academic resource ecosystem and
study platform developed for university students, educators, and administrators.
The platform unifies:
  - Academic Book & Study Material Catalog: Full catalog management, course categorization
    (BCA, DCA, PGDCA), semester filtering, spotlight sections (BCA Spotlight, DCA Spotlight,
    PGDCA Spotlight, Featured Books, Best Sellers, New Arrivals), custom ordering, syllabus
    topics with page index mapping, and detailed modal inspection.
  - University Question Papers & Solution Bank: Hierarchical indexing of academic
    universities, courses, subjects, Q&A pairs, and past examination PDFs with course selector tabs.
  - Programming Solutions Hub: Code solution repository supporting multiple
    programming languages (.NET, C, C#, C++, Java, Python), syntax formatting, how-to-run instructions,
    and AI-driven semantic duplicate detection.
  - Document & Question Extraction Engine: In-browser and server-side ingestion
    of PDF and DOCX files with baseline indentation recovery and automated
    AI-powered question-and-answer extraction.
  - Role-Based Access Control (RBAC): Differentiated student and administrator experiences
    with an exhaustive Admin Dashboard for catalog control, user moderation,
    error logging, maintenance mode toggling, and API heartbeat monitors.
  - Progressive Web App (PWA): Native-like mobile and desktop installation with
    offline fallback resilience.

5. FRONTEND ARCHITECTURE, ROUTING & COMPONENT TREE
================================================================================
A. Dynamic Chunk Reload Healing:
   When Vite builds are deployed, asset chunk hashes change. If a client has an older
   version cached, two failure modes can occur:
   1. JS dynamic import failure: lazyWithRetry catches this, sets a sessionStorage flag,
      and triggers a clean window reload once.
   2. CSS preload chunk failure: Vite injects <link rel="modulepreload"> for CSS chunks.
      App.jsx listens to 'vite:preloadError' and reloads with a 15s cooldown.

6. STATE MANAGEMENT & REACT CONTEXT SIGNATURES
================================================================================
1. AuthContext (src/context/AuthContext.jsx):
   - Hook: useAuth()
   - State:
     * user: { uid, email, role: 'admin'|'user', username, photoURL, createdAt } | null
     * loading: boolean
   - Methods:
     * login(email, password) -> Promise<UserCredential>
     * register(email, password, role, username) -> Promise<UserCredential>
       (Creates Auth user, sets Firestore /users/{uid} doc, and calls POST /api/send-welcome-email)
     * logout() -> Promise<void>
     * checkAccountExists(email) -> Promise<boolean>
     * updateUsername(newUsername) -> Promise<void>
     * loginWithGoogle() -> Promise<UserCredential>
       (Calls signInWithPopup(auth, googleProvider). If user document does not exist in Firestore,
        creates user doc with role: 'user' and calls POST /api/send-welcome-email)

2. BookContext (src/context/BookContext.jsx):
   - Hook: useBooks()
   - State:
     * books: Array<BookObject> (Real-time onSnapshot from collection 'books')
     * loading: boolean
   - Methods:
     * addBook(newBook) -> Promise<void> (Calls addDoc, then notifies IndexNow for '/books')
     * removeBook(id) -> Promise<void> (Calls deleteDoc, then notifies IndexNow for '/books')
     * updateBook(id, updates) -> Promise<void> (Calls updateDoc, then notifies IndexNow for '/books')
     * addProgrammingSolution(bookId, solution) -> Promise<string (solutionId)>
     * updateProgrammingSolution(bookId, solutionId, updates) -> Promise<void>
     * deleteProgrammingSolution(bookId, solutionId) -> Promise<void>
     * getBooksBySection(sectionName) -> Array<BookObject> (Sorted by sectionOrders[sectionName])
     * getBooksByCategory(category) -> Array<BookObject>

3. QuestionContext (src/context/QuestionContext.jsx):
   - Hook: useQuestions()
   - State:
     * questions: Array<QuestionObject> (CollectionGroup 'questions')
     * questionPdfs: Array<PdfObject> (CollectionGroup 'questionPdfs')
     * universities: Array<UniversityObject> (Collection 'universities')
     * loading: boolean
   - Methods:
     * addQuestion(newQuestion) -> Promise<void> (Target: /courses/{course}/subjects/{subject}/questions)
     * updateQuestion(id, updates, parentPath) -> Promise<void>
     * deleteQuestion(id, parentPath) -> Promise<void>
     * addSubject(subjectData: { name, course }) -> Promise<void>
     * deleteSubject(course, subjectName) -> Promise<void> (Cascading delete of child questions)
     * addUniversity(universityData) -> Promise<void>
     * deleteUniversity(id) -> Promise<void>
     * addQuestionPdfs(course, subject, pdfLinks) -> Promise<void>
     * updateQuestionPdf(docPath, updates) -> Promise<void>
     * deleteQuestionPdf(docPath) -> Promise<void>
     * getSubjects(course) -> CollectionReference

4. ThemeContext (src/context/ThemeContext.jsx):
   - Hook: useTheme()
   - State: theme ('light' | 'dark' | 'vintage' | 'ocean' | 'midnight' | 'nord' | 'sunset')
   - Default: 'light' (or read from localStorage.getItem('theme'))
   - Methods: setTheme(themeName) -> void
   - Synchronization: Writes to localStorage key 'theme', updates document.documentElement attribute data-theme="<theme>", and applies body class <theme>-mode.

11. SECURITY RULES SPECIFICATION (FIRESTORE.RULES)
================================================================================
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAuthenticated() {
      return request.auth != null;
    }
    function isAdmin() {
      return isAuthenticated() &&
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin";
    }
    
    match /users/{userId} {
      allow read, write: if isAuthenticated() && (request.auth.uid == userId || isAdmin());
    }
    match /books/{bookId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /courses/{course}/subjects/{subject}/questions/{questionId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /courses/{course}/subjects/{subject}/questionPdfs/{pdfId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /{path=**}/questions/{q} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /{path=**}/questionPdfs/{pdf} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /universities/{universityId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /stats/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /daily_stats/{document=**} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /system_status/{doc} {
      allow read, write: if isAdmin();
    }
    match /client_errors/{err} {
      allow create: if true;
      allow read, update, delete: if isAdmin();
    }
  }
}

20. DOCUMENT PARSING ENGINE (PDF & DOCX PROCESSING)
================================================================================
- Location: src/utils/documentUtils.js.
- PDF Text & Hierarchy Extraction (pdfjs-dist):
  - Uses CDN worker: //unpkg.com/pdfjs-dist@{version}/build/pdf.worker.min.mjs.
  - Smart Baseline Indentation Algorithm:

       semantic HTML <ul><li> or <p> tags with Quill indentation classes.

  - Ingests raw DOCX ArrayBuffer and converts structured document elements directly into clean HTML.

24. STRICT ENGINEERING CONVENTIONS & QUALITY RULES
================================================================================
1. NO DIRECT DOM MANIPULATION:
   Never write direct DOM queries (e.g. document.getElementById, document.querySelector,
   element.innerHTML) unless explicitly commanded. All UI updates must flow through React
   state, controlled components, or useRef hooks.

2. NO EMOJIS:
   Do not introduce emojis into source code, user interfaces, logs, or commit messages
   unless explicitly requested by the user.

3. PRE-MODIFICATION ERROR CHECK:
   Before making code changes, inspect recent runtime errors logged in Firebase Firestore
   under the 'client_errors' collection (via ErrorLoggerService / Admin Dashboard) to identify
   and address existing runtime defects first.

4. CSS VARIABLES & THEME CONSISTENCY MANDATE:
   Always utilize semantic CSS variables defined in src/themes.css (--primary-color,
   --card-bg, --text-color, --border-adaptive, --on-accent, etc.) instead of hardcoding
   hex/RGB values. For accent elements (.pdf-card-course, .pdf-view-btn, .questions-search-btn,
   .pdf-edit-btn, .course-tab-pill.active, .lang-tab-pill.active), text and icon strokes are
   governed by --on-accent (#000000 in dark, #6e352b in vintage, #1e40af in light, and
   var(--surface-text) in ocean, midnight, nord, sunset).
   When making theme-related changes, ensure they are applied across all pages and maintain
   proper contrast between text colour and background colour.

5. CASE-SENSITIVITY COMPLIANCE:
   macOS is case-insensitive while Linux deployment environments are case-sensitive.
   Ensure all file imports match exact filesystem casing and run python3 check.py.

6. CONTINUOUS DOCUMENTATION SYNCHRONIZATION:
   Whenever changes are made to code, functionality, endpoints, services, or environment
   variables, immediately update both DEVELOPER_GUIDE.txt and AI_AGENTS_GUIDE.txt.
