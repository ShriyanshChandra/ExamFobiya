1. EXECUTIVE SUMMARY & CORE MISSION
================================================================================
ExamFobiya is a comprehensive, production-grade academic resource ecosystem and
digital bookstore developed for university students, educators, and administrators.
The platform unifies:
  - Academic Book Catalog & Bookstore: Full inventory management, categorization,
    spotlight sections (Best Sellers, New Arrivals, Featured), custom ordering,
    and detailed modal inspection.
  - University Question Papers & Solution Bank: Hierarchical indexing of academic
    universities, courses, subjects, Q&A pairs, and past examination PDFs.
  - Programming Solutions Hub: Code solution repository supporting multiple
    programming languages, syntax formatting, algorithmic complexities, and
    AI-driven semantic duplicate detection.
  - Document & Question Extraction Engine: In-browser and server-side ingestion
    of PDF and DOCX files with baseline indentation recovery and automated
    AI-powered question-and-answer extraction.
  - Network Diagnostics & AI Optimization: Built-in network speed test tool that
    evaluates latency, upload/download throughput, and generates tailored AI
    bandwidth optimization suggestions.
  - Role-Based Access Control (RBAC): Differentiated student/customer experiences
    and an exhaustive Admin Dashboard with inventory control, user moderation,
    error logging, maintenance mode toggling, and API heartbeat monitors.
  - Progressive Web App (PWA): Native-like mobile and desktop installation with
    offline fallback resilience.

C. Dynamic Chunk Healing (lazyWithRetry):
   When Vite builds are deployed, asset chunk hashes change. If a client has an older
   version cached, navigating to a new route might fail with a dynamic import error.
   The lazyWithRetry wrapper in src/App.jsx catches this error, stores a flag in
   window.sessionStorage ('chunk_retry_refreshed'), and performs a clean reload to
   fetch the latest production bundle without crashing the user's session.

4. BACKEND ARCHITECTURE, MIDDLEWARE & SERVER LOGIC
================================================================================
A. Core Components:
   backend/
   ├── routes/
   │   └── ai.js              : AI controller containing Gemini prompt logic and handlers
   ├── server.js              : Main Express server, middleware, routes, crons, keep-alives
   ├── serviceAccountKey.json : Local development Firebase Admin SDK credentials
   ├── package.json           : Backend dependencies and scripts
   └── .env                   : Backend environment variables and secrets

B. Server Initialization Sequence:
   1. require('dotenv').config() executes immediately before any other module load.
   2. Firebase Admin SDK initializes:
      - In production (e.g. on Render): Reads process.env.FIREBASE_SERVICE_ACCOUNT (JSON string).
      - In development: Loads backend/serviceAccountKey.json from disk.
      - If credentials fail to load, the server logs a fatal error and terminates (process.exit(1)).
   3. Express application created with CORS and JSON body parser.
   4. Route controllers attached.
   5. Server listens on process.env.PORT (default 5000) and HOST.
   6. On startup, checkAndRunKeepAlivePings() triggers an initial health check, followed
      by an automated recurring interval check every 24 hours.

C. Authentication & Authorization Middleware (verifyAdminToken):
   - Extracts Bearer token from the 'Authorization' HTTP header.
   - Verifies the ID token cryptographically using Firebase Admin: getAuth().verifyIdToken(idToken).
   - Looks up the user's profile document in Firestore: /users/{decodedToken.uid}.
   - Confirms userDoc.data().role === 'admin'. If not met, returns HTTP 403 Forbidden.
   - Attaches req.adminUser = { uid, email, role } to the request object.

6. THIRD-PARTY SERVICES, CLOUD PLATFORMS & INTEGRATIONS
================================================================================
1. Google Cloud Platform / Firebase:
   - Firebase Authentication: Identity management (email/password).
   - Cloud Firestore: Primary multi-region document store.
   - Firebase Storage: Binary file storage for book covers and question documents.
   - Firebase Hosting: Static asset delivery with 1-year immutable caching for static assets.

2. Brevo (Sendinblue):
   - High-deliverability transactional email delivery using REST API v3 over HTTPS.
   - Replaces traditional SMTP port connections (ports 25, 465, 587) which are frequently
     blocked or throttled by cloud hosting providers like Render.
   - Sends HTML styled emails for 6-digit registration OTPs and administrator password resets.

3. Google Gemini AI:
   - LLM infrastructure providing real-time text analysis, structured JSON parsing, and
     semantic similarity vector comparisons across academic content.

4. IndexNow Protocol (Microsoft Bing, Yandex, Seznam, Naver):
   - Push protocol to instantly notify search engine spiders of newly created or edited URLs.
   - Minimizes the latency between publishing academic resources and appearing in search results.

5. Cloud Hosting:
   - Render: Deploys the Node.js Express server with automated build and deployment pipelines.
   - Vercel: Alternative hosting platform for the frontend with single-page app rewrite configuration.

8. AI INTEGRATIONS & MODEL ASSIGNMENTS (GOOGLE GEMINI)
================================================================================
ExamFobiya leverages Google Gemini generative AI across three distinct workflows:

1. Internet Speed Optimization Suggestions:
   - Endpoint: POST /api/ai/suggestions
   - Controller: backend/routes/ai.js (generateSuggestions)
   - Model Assigned: gemini-2.5-flash
   - Prompt Purpose: Analyzes download speed, upload speed, latency (ping), browser type,
     time of day, and ratings across gaming, streaming, browsing, and calling to generate
     exactly 4 concise, actionable, single-sentence recommendations.

2. Document & Text Question Parsing:
   - Endpoint: POST /api/ai/parse-questions
   - Controller: backend/routes/ai.js (parseQuestions)
   - Model Assigned: gemini-2.5-flash
   - Prompt Purpose: Ingests unstructured academic text or OCR output, detects question-answer
     boundaries, strips 'Q:'/'A:' prefixes, preserves all HTML formatting (<ul>, <ol>, <li>,
     <strong>, <em>, <p>, <br>), and returns a strict JSON array of question objects.

3. Programming Solution Semantic Duplicate Detection:
   - Endpoint: POST /api/ai/check-similar-programming-solutions
   - Controller: backend/routes/ai.js (checkSimilarProgrammingSolutions)
   - Model Assigned: gemini-3.6-flash
   - Access Control: Restricted to Admin via verifyAdminToken.
   - Prompt Purpose: Compares a new programming question against existing solutions in the
     same language. Matches based on underlying algorithmic tasks (score >= 0.72) rather than
     generic boilerplate code. Returns at most 3 matches with similarity scores and rationale.

4. Automated API Keep-Alive Heartbeat:
   - Handler: backend/server.js (sendGeminiKeepAlivePing)
   - Model Assigned: gemini-2.5-flash
   - Purpose: Sends lightweight generation requests every 25 days to prevent Google AI Studio
     API keys from going stale due to inactivity.

9. TRANSACTIONAL EMAIL INFRASTRUCTURE (BREVO API V3)
================================================================================
- Protocol: Direct HTTPS POST to https://api.brevo.com/v3/smtp/email using Node.js https client.
- Authentication: Header 'api-key' loaded from process.env.EMAIL_PASS.
- Workflows:
  1. Registration OTP:
     - Endpoint: POST /send-otp (purpose: 'register')
     - Generates cryptographically random 6-digit OTP.
     - Saves OTP document in /otps/{normalizedEmail} with a 10-minute expiry timestamp.
     - Delivers responsive HTML email with highlighted OTP card.
  2. Password Reset (User Self-Service & Admin Triggered):
     - Endpoints: POST /api/auth/send-password-reset and POST /api/admin/send-password-reset
     - Generates official Firebase password reset link with action code settings.
     - Encapsulates action code into customized application URL: /reset-password?oobCode=...&email=...
     - Dispatches branded HTML email featuring a gradient header, reset button, and raw URL fallback.

10. SEARCH ENGINE INDEXING PIPELINE (INDEXNOW)
================================================================================
- Service: src/services/IndexNowService.js & backend/server.js (/api/indexnow/notify).
- Protocol: IndexNow API (https://api.indexnow.org/indexnow).

  2. The service dispatches an asynchronous, fire-and-forget POST request to the backend.
  3. The backend batches up to 10,000 URLs and submits them to api.indexnow.org with host
     'www.examfobiya.com' and key 'c3b77bf259f243af99818667d9215013'.
  4. Search engines (Bing, Yandex, etc.) immediately schedule targeted crawl tasks.

C. API Keys Keep-Alive Monitor:
   - Backend service tracking inactivity timeouts for external APIs (Brevo and Gemini).
   - Executes automatic pings if 25 days have elapsed since the last recorded ping.
   - Status stored in /system_status/api_keepalive.
   - Admins can view masked keys and trigger manual pings directly from the Admin Dashboard.

13. DOCUMENT PARSING ENGINE (PDF & DOCX PROCESSING)
================================================================================
- Location: src/utils/documentUtils.js.
- PDF Text & Hierarchy Extraction (pdfjs-dist):
  - Uses CDN worker: //unpkg.com/pdfjs-dist@{version}/build/pdf.worker.min.mjs.
  - Smart Baseline Indentation Algorithm:
    1. Extracts text items with their geometric transform coordinates (x, y).
    2. Builds an X-coordinate histogram to determine the genuine left margin threshold
       (ignoring outliers like page numbers or margin artifacts).
    3. Computes indentation levels (approx 35 units per tab level).
    4. Normalizes global indentation so minimum indentation is zero.
    5. Post-processes orphan bullets ('●', '•', 'o', '*', '-', '·') and wraps text in
       semantic HTML <ul><li> or <p> tags with Quill indentation classes.
- DOCX Extraction (mammoth):
  - Ingests raw DOCX ArrayBuffer and converts structured document elements directly into clean HTML.

15. DEVELOPMENT SETUP, COMMANDS & DEPLOYMENT PROTOCOLS
================================================================================
1. Local Prerequisites:
   - Node.js (v18.x, v20.x, or later)
   - Python 3 (for case-sensitivity validation)
   - npm (v9.x or later)

2. Initial Installation:
   # Install root frontend dependencies
   npm install
   # Install backend dependencies
   cd backend && npm install && cd ..

3. Running Development Servers:
   npm run dev
   # Runs concurrent processes:
   #   1. Vite dev server at http://localhost:5173
   #   2. Express backend server at http://127.0.0.1:5000

4. Validation & Quality Checks:
   # Check for case-sensitive import mismatches (run once per session)
   python3 check.py

5. Production Build:
   npm run build
   # Generates optimized production bundles in dist/

6. Deployment Configurations:
   - Backend: Hosted on Render with Start Command 'node server.js' and Root Directory 'backend'.
     Requires setting FIREBASE_SERVICE_ACCOUNT, EMAIL_PASS, GEMINI_API_KEY, and other backend env vars.
   - Frontend: Hosted on Firebase Hosting (firebase.json) or Vercel (vercel.json) with SPA rewrites.

16. STRICT ENGINEERING CONVENTIONS & QUALITY RULES
================================================================================
1. NO DIRECT DOM MANIPULATION:
   Never write direct DOM queries (e.g. document.getElementById, document.querySelector,
   element.innerHTML) unless explicitly commanded. All UI updates must flow through React
   state, controlled components, or useRef hooks.

2. NO EMOJIS:
   Do not introduce emojis into source code, user interfaces, logs, or commit messages
   unless explicitly requested by the user.

3. PRE-MODIFICATION ERROR CHECK:
   Before making code changes, inspect recent runtime errors logged in Firebase Firestore
   under the 'client_errors' collection (via ErrorLoggerService / Admin Dashboard) to identify
   and address existing runtime defects first.

4. CSS VARIABLES MANDATE:
   Always utilize semantic CSS variables defined in src/themes.css (--primary-color,
   --card-bg, --text-color, --border-adaptive, etc.) instead of hardcoding hex/RGB values.

5. CASE-SENSITIVITY COMPLIANCE:
   macOS is case-insensitive while Linux deployment environments are case-sensitive.
   Ensure all file imports match exact filesystem casing and run python3 check.py.

6. CONTINUOUS DOCUMENTATION SYNCHRONIZATION:
   Whenever changes are made to code, functionality, endpoints, services, or environment
   variables, immediately update both DEVELOPER_GUIDE.txt and AI_AGENTS_GUIDE.txt.
