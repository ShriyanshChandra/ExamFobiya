1. SYSTEM OPERATIONAL INVARIANTS & AGENT DIRECTIVES
================================================================================
All AI coding agents modifying or rebuilding this codebase MUST strictly comply with:

1. NO DIRECT DOM MANIPULATION:
   Never write direct DOM queries (document.getElementById, document.querySelector,
   document.getElementsByClassName, element.innerHTML, etc.) unless explicitly commanded.
   All DOM operations must be driven declaratively through React state, props, controlled
   components, or useRef handles.

2. STRICT ZERO EMOJIS POLICY:
   Never insert emojis into code, comments, documentation, UI elements, alerts, emails,
   commit messages, or agent responses unless explicitly commanded by the user.

3. PRE-MODIFICATION ERROR CHECK:
   Before modifying project code, inspect recent runtime client errors stored in Firestore
   under the 'client_errors' collection (via ErrorLoggerService / Admin Dashboard) to triage
   and address existing production runtime defects first.

4. CASE-SENSITIVITY COMPLIANCE:
   The development host is macOS (case-insensitive file system), but deployment targets
   (Linux on Render / Vercel / Firebase Hosting) are case-sensitive. All module imports
   must match exact file casing. Run 'python3 check.py' once per session to validate imports.

5. CSS VARIABLES & THEME CONSISTENCY MANDATE:
   Never hardcode raw hex, RGB, or HSL color literals in component CSS. Always use the semantic
   variables defined in src/themes.css (--primary-color, --card-bg, --text-color, --border-adaptive, etc.).
   When making theme-related changes, apply them across all 7 themes and maintain proper contrast.

6. CONTINUOUS DOCUMENTATION SYNCHRONIZATION:
   Whenever changes are made to code, functionality, endpoints, services, or environment
   variables, immediately update both DEVELOPER_GUIDE.txt and AI_AGENTS_GUIDE.txt.

4. APPLICATION ROUTING, CHUNK HEALING & GUARD ARCHITECTURE (App.jsx)
================================================================================
A. Dynamic Chunk Reload Healing Implementation:
   All page routes must be dynamically imported using the lazyWithRetry utility to
   gracefully recover from outdated chunks after production deployments:

   const lazyWithRetry = (componentImport) => React.lazy(async () => {
     const pageHasAlreadyBeenForceRefreshed = JSON.parse(
       window.sessionStorage.getItem('page-has-been-force-refreshed') || 'false'
     );
     try {
       const component = await componentImport();
       window.sessionStorage.setItem('page-has-been-force-refreshed', 'false');
       return component;
     } catch (error) {
       if (!pageHasAlreadyBeenForceRefreshed) {
         window.sessionStorage.setItem('page-has-been-force-refreshed', 'true');
         return window.location.reload();
       }
       throw error;
     }
   });

   Additionally, Vite CSS preload chunk failures are caught by a global event listener:
   window.addEventListener('vite:preloadError', (event) => {
     event.preventDefault();
     const lastReload = parseInt(localStorage.getItem('vite_preload_reload_ts') || '0', 10);
     const now = Date.now();
     if (now - lastReload > 15000) {
       localStorage.setItem('vite_preload_reload_ts', String(now));
       window.location.reload();
     }
   });

C. Maintenance Guard Flow:
   - MaintenanceGuard wraps the entire route tree inside BrowserRouter.
   - Listens via Firestore onSnapshot to /stats/system_settings (field: maintenanceMode: boolean).
   - Supplemental 8-second polling interval ensures recovery if WebSocket drops.
   - When maintenanceMode is true:
     * Standard users navigating to any public or protected page are routed to /maintenance.
     * Login (/login) and Admin (/admin) routes remain accessible.
     * Logged-in admins see a persistent top amber alert bar with direct access to Admin Dashboard.
   - When maintenanceMode is switched false:
     * Users currently on /maintenance are automatically redirected to Home (/).

5. STATE MANAGEMENT & REACT CONTEXT SIGNATURES
================================================================================
1. AuthContext (src/context/AuthContext.jsx):
   - Hook: useAuth()
   - State:
     * user: { uid, email, role: 'admin'|'user', username, photoURL, createdAt } | null
     * loading: boolean
   - Methods:
     * login(email, password) -> Promise<UserCredential>
     * register(email, password, role, username) -> Promise<UserCredential>
       (Creates Auth user, sets Firestore /users/{uid} doc, and calls POST /api/send-welcome-email)
     * logout() -> Promise<void>
     * checkAccountExists(email) -> Promise<boolean>
     * updateUsername(newUsername) -> Promise<void>
     * loginWithGoogle() -> Promise<UserCredential>
       (Calls signInWithPopup(auth, googleProvider). If user document does not exist in Firestore,
        creates user doc with role: 'user' and calls POST /api/send-welcome-email)

2. BookContext (src/context/BookContext.jsx):
   - Hook: useBooks()
   - State:
     * books: Array<BookObject> (Real-time onSnapshot from collection 'books')
     * loading: boolean
   - Methods:
     * addBook(newBook) -> Promise<void> (Calls addDoc, then notifies IndexNow for '/books')
     * removeBook(id) -> Promise<void> (Calls deleteDoc, then notifies IndexNow for '/books')
     * updateBook(id, updates) -> Promise<void> (Calls updateDoc, then notifies IndexNow for '/books')
     * addProgrammingSolution(bookId, solution) -> Promise<string (solutionId)>
     * updateProgrammingSolution(bookId, solutionId, updates) -> Promise<void>
     * deleteProgrammingSolution(bookId, solutionId) -> Promise<void>
     * getBooksBySection(sectionName) -> Array<BookObject> (Sorted by sectionOrders[sectionName])
     * getBooksByCategory(category) -> Array<BookObject>

3. QuestionContext (src/context/QuestionContext.jsx):
   - Hook: useQuestions()
   - State:
     * questions: Array<QuestionObject> (CollectionGroup 'questions')
     * questionPdfs: Array<PdfObject> (CollectionGroup 'questionPdfs')
     * universities: Array<UniversityObject> (Collection 'universities')
     * loading: boolean
   - Methods:
     * addQuestion(newQuestion) -> Promise<void> (Target: /courses/{course}/subjects/{subject}/questions)
     * updateQuestion(id, updates, parentPath) -> Promise<void>
     * deleteQuestion(id, parentPath) -> Promise<void>
     * addSubject(subjectData: { name, course }) -> Promise<void>
     * deleteSubject(course, subjectName) -> Promise<void> (Cascading delete of child questions)
     * addUniversity(universityData) -> Promise<void>
     * deleteUniversity(id) -> Promise<void>
     * addQuestionPdfs(course, subject, pdfLinks) -> Promise<void>
     * updateQuestionPdf(docPath, updates) -> Promise<void>
     * deleteQuestionPdf(docPath) -> Promise<void>
     * getSubjects(course) -> CollectionReference

4. ThemeContext (src/context/ThemeContext.jsx):
   - Hook: useTheme()
   - State: theme ('light' | 'dark' | 'vintage' | 'ocean' | 'midnight' | 'nord' | 'sunset')
   - Default: 'light' (or read from localStorage.getItem('theme'))
   - Methods: setTheme(themeName) -> void
   - Synchronization: Writes to localStorage key 'theme', updates document.documentElement attribute data-theme="<theme>", and applies body class <theme>-mode.

B. Security Rules Core (firestore.rules):
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAuthenticated() {
      return request.auth != null;
    }
    function isAdmin() {
      return isAuthenticated() &&
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin";
    }
    
    match /users/{userId} {
      allow read, write: if isAuthenticated() && (request.auth.uid == userId || isAdmin());
    }
    match /books/{bookId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /courses/{course}/subjects/{subject}/questions/{questionId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /courses/{course}/subjects/{subject}/questionPdfs/{pdfId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /{path=**}/questions/{q} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /{path=**}/questionPdfs/{pdf} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /universities/{universityId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /stats/{doc} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /daily_stats/{document=**} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /system_status/{doc} {
      allow read, write: if isAdmin();
    }
    match /client_errors/{err} {
      allow create: if true;
      allow read, update, delete: if isAdmin();
    }
  }
}

15. DOCUMENT PARSING PIPELINE (PDF SMART BASELINE & DOCX MAMMOTH)
================================================================================
- File: src/utils/documentUtils.js
- PDF Parsing Algorithm (pdfjs-dist):
  1. Extract items with text item.str and coordinate item.transform[4] (X-position).
  2. Build X-histogram with bucketSize = 5.
  3. Set significance threshold at 10% of total items to ignore marginal artifacts/numbers.
  4. Identify minX as the leftmost significant bucket.
  5. Compute indentLevel = Math.floor((item.x - minX) / 35).
  6. Shift global indent level to 0 baseline.
  7. Detect orphan bullet lines ('●', '•', 'o', '*', '-', '·') and merge into list items.
  8. Output HTML <ul><li> or <p> tags with Quill classes (ql-indent-N).
- DOCX Parsing (mammoth):
  Direct conversion from ArrayBuffer to clean HTML via mammoth.convertToHtml().

19. CRITICAL GOTCHAS, EDGE CASES & IMPLEMENTATION RULES
================================================================================
1. Dynamic Chunk Reloads:
   Always use lazyWithRetry(() => import('...')) when adding new page routes in App.jsx
   to prevent white-screen crashes after new production builds are deployed.

2. CollectionGroup Queries:
   When updating or deleting documents fetched via collectionGroup(db, 'questions') or
   collectionGroup(db, 'questionPdfs'), you must use the full document path (doc.ref.path)
   because document IDs alone are not sufficient to construct subcollection references.

3. Keep-Alive Heartbeat:
   The backend server automatically pings Brevo and Gemini APIs on startup and every 24 hours.
   Pings only execute against external APIs if 25 days have elapsed since the last recorded ping.

4. Email Delivery Over HTTPS:
   Never replace Brevo REST API v3 HTTPS calls with standard Nodemailer SMTP transport, as
   Render and other containerized cloud platforms block outgoing SMTP ports by default.

5. Welcome Email Idempotency:
   Never trigger welcome emails inside global auth listeners (onAuthStateChanged). Always trigger
   exclusively within explicit register() and first-time loginWithGoogle() handlers, guarded by
   backend in-memory locks and persistent Firestore /welcome_emails records.

6. Strict Zero Emojis:
   Maintain zero emojis across all code, comments, email templates, UI elements, and documentation.

7. Synchronized Documentation:
   Whenever any backend route, Firestore collection, environment variable, or frontend feature
   is created or modified, both DEVELOPER_GUIDE.txt and AI_AGENTS_GUIDE.txt must be updated
   in the same turn.
