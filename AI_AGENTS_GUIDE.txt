1. SYSTEM OPERATIONAL INVARIANTS & AGENT DIRECTIVES
================================================================================
All AI coding agents modifying this codebase MUST comply with the following invariants:

1. NO DIRECT DOM MANIPULATION:
   Never write imperative DOM queries (document.getElementById, document.querySelector,
   document.getElementsByClassName, element.innerHTML, etc.) unless explicitly commanded.
   All DOM operations must be driven declaratively through React state, props, controlled
   components, or useRef handles.

2. NO EMOJIS:
   Never insert emojis into code, comments, documentation, UI elements, alerts, or responses
   unless explicitly requested by the user.

3. PRE-MODIFICATION ERROR CHECK:
   Before modifying project code, check recent runtime client errors stored in Firestore
   under the 'client_errors' collection (via ErrorLoggerService / Admin Dashboard) to triage
   and fix existing production runtime issues first.

4. CASE-SENSITIVITY COMPLIANCE:
   The development host is macOS (case-insensitive file system), but deployment environments
   (Linux on Render/Vercel) are case-sensitive. All module imports must match exact file
   casing. Run 'python3 check.py' only once per session to validate imports.

5. CSS VARIABLES MANDATE:
   Never hardcode raw hex, RGB, or HSL color literals in component CSS. Always use the semantic
   variables defined in src/themes.css (--primary-color, --card-bg, --text-color, --border-adaptive, etc.).

6. CONTINUOUS DOCUMENTATION SYNCHRONIZATION:
   Whenever changes are made to code, functionality, endpoints, services, or environment
   variables in any conversation, immediately update both DEVELOPER_GUIDE.txt and AI_AGENTS_GUIDE.txt.

5. FIRESTORE DATABASE SCHEMA & SECURITY RULES SPECIFICATION
================================================================================
A. Collections & Schemas:
1. /users/{userId}
   * Document ID: Firebase Auth UID
   * Types: { email: string, role: "admin"|"user", username: string, createdAt: Timestamp|string }

2. /books/{bookId}
   * Document ID: Auto-generated string
   * Types: {
       title: string, category: "BCA"|"DCA"|"PGDCA", semester: string|null, author: string,
       sections: string[], sectionOrders: Record<string, number|"Temp">, image: string,
       contents: string, syllabusPageNumbers: string[], hasProgrammingSolution?: boolean,
       programmingSolutions?: Array<{
         id: string, title: string, language: string, code: string, description: string,
         input?: string, output?: string
       }>,
       createdAt: string
     }

3. /courses/{course}/subjects/{subject}/questions/{questionId}
   * Types: { question: string (HTML), answer: string (HTML), year: string, marks: string, course: string, subject: string, createdAt: Timestamp|string }

4. /courses/{course}/subjects/{subject}/questionPdfs/{pdfId}
   * Types: { label: string, url: string, month: string, year: string, course: string, subject: string, uploadedAt: string }

5. /universities/{universityId}
   * Types: { name: string, location: string, courses: string[], createdAt: Timestamp|string }

6. /otps/{normalizedEmail}
   * Types: { code: string (6 digits), expiresAt: number (ms timestamp) }

7. /stats/system_settings
   * Types: { maintenanceMode: boolean, updatedAt: string }

8. /system_status/api_keepalive
   * Types: { lastPingAt: number, lastPingFormatted: string, brevoStatus: object, geminiStatus: object, updatedAt: string }

9. /client_errors/{errorId}
   * Types: { message: string, stack: string, componentStack: string, type: string, url: string, userAgent: string, userId: string, userEmail: string, resolved: boolean, date: string, timestamp: FieldValue, createdAt: string }

B. Security Rules Core (firestore.rules):
   function isAdmin() {
     return request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin";
   }
   - /users/{userId}: allow read, write if request.auth.uid == userId || isAdmin()
   - /books/{bookId}: allow read if true; allow write if isAdmin()
   - /courses/**, /universities/**: allow read if true; allow write if isAdmin()
   - /{path=**}/questions/{q}: allow read if true; allow write if isAdmin()
   - /{path=**}/questionPdfs/{pdf}: allow read if true; allow write if isAdmin()
   - /stats/**, /daily_stats/**: allow read if true; allow write if isAdmin()
   - /client_errors/{err}: allow create if true; allow read, update, delete if isAdmin()

   - Body: { "email": string, "otp": string }
   - Logic: Compares OTP against /otps/{email}. Deletes OTP upon successful verification.
   - Response: 200 { "message": "OTP Verified successfully" } | 400

   - Body: { "email": string, "otp": string, "newPassword": string }

7. AI MODELS, PROMPT PIPELINES & RESPONSE PARSERS (GOOGLE GEMINI)
================================================================================
1. Question Parsing Pipeline (backend/routes/ai.js):
   - Model: "gemini-3.6-flash"
   - Rules: Retain HTML tags (<ul>, <ol>, <li>, <strong>, <em>, <p>, <br>), strip "Q:", "A:", "Question:", "Answer:" prefixes, enforce JSON array output shape [{"question": "...", "answer": "..."}].
   - Markdown sanitization: Strips ```json and ``` code block fences before JSON.parse().

2. Duplicate Solution Detection Pipeline (backend/routes/ai.js):
   - Model: "gemini-3.6-flash"
   - Prompt constraint: Compare question intent, return only matches with score >= 0.72, at most 3 items, JSON shape: {"matches":[{"id":"...","score":0.0,"reason":"..."}]}.
   - Sanitization: Validates that returned match IDs exist in candidate set and enforces score threshold >= 0.72.

12. DOCUMENT PARSING PIPELINE (PDF SMART BASELINE & DOCX MAMMOTH)
================================================================================
- File: src/utils/documentUtils.js
- PDF Parsing Algorithm (pdfjs-dist):
  1. Extract items with text item.str and coordinate item.transform[4] (X-position).
  2. Build X-histogram with bucketSize = 5.
  3. Set significance threshold at 10% of total items to ignore marginal artifacts/numbers.
  4. Identify minX as the leftmost significant bucket.
  5. Compute indentLevel = Math.floor((item.x - minX) / 35).
  6. Shift global indent level to 0 baseline.
  7. Detect orphan bullet lines ('●', '•', 'o', '*', '-', '·') and merge into list items.
  8. Output HTML <ul><li> or <p> tags with Quill classes (ql-indent-N).
- DOCX Parsing (mammoth):
  Direct conversion from ArrayBuffer to clean HTML via mammoth.convertToHtml().

14. CRITICAL GOTCHAS, EDGE CASES & IMPLEMENTATION RULES
================================================================================
1. Dynamic Chunk Reloads:
   Always use lazyWithRetry(() => import('...')) when adding new page routes in App.jsx
   to prevent white-screen crashes after new production builds are deployed.

2. CollectionGroup Queries:
   When updating or deleting documents fetched via collectionGroup(db, 'questions') or
   collectionGroup(db, 'questionPdfs'), you must use the full document path (doc.ref.path)
   because document IDs alone are not sufficient to construct subcollection references.

3. Keep-Alive Heartbeat:
   The backend server automatically pings Brevo and Gemini APIs on startup and every 24 hours.
   Pings only execute against external APIs if 25 days have elapsed since the last recorded ping.

4. Email Delivery Over HTTPS:
   Never replace Brevo REST API v3 HTTPS calls with standard Nodemailer SMTP transport, as
   Render and other containerized cloud platforms block outgoing SMTP ports by default.

5. Synchronized Documentation:
   Whenever any backend route, Firestore collection, environment variable, or frontend feature
   is created or modified, both DEVELOPER_GUIDE.txt and AI_AGENTS_GUIDE.txt must be updated
   in the same turn.
